球接进来之后，问题变成了另一件事：除了那颗球，屏幕上什么都没有。

一整屏纯黑，一颗球漂在中间，看三秒很高级，看三十秒会怀疑是不是加载卡住了。我想要一点东西在黑里慢慢动，但不能抢戏，尤其不能碰到球。

所以背景全部用 CSS 做，压在 `canvas` 下面（`z-index:-1`），一个像素都不经过 shader。

- **星尘**：两层平铺的点阵，各自朝不同方向漂。位移量取了 tile 尺寸的整数倍，所以循环到末尾时看不出接缝；
- **刻度环**：两圈极淡的虚线圆环，一圈 118 秒、一圈 190 秒，反向转；
- **辉光**：和球同心的蓝紫光晕，8.5 秒一呼一吸；
- **球底反光**：一小片模糊的椭圆光，让人相信球是悬着的，不是贴上去的；
- **微光颗粒**：球底附近几颗小点，错开时间往上升然后消失。

所有尺寸都写成一个变量：

```
:root { --d: calc(min(100vw, 100vh) * 0.66); }
```

球在画面里的直径，实测大约是视口短边的 0.66 倍（和 shader 里那个 `contourRad ≈ 0.67` 对得上）。所以环的半径、辉光的大小、反光的偏移，全部乘 `--d`——换成手机、平板、带鱼屏，装饰都会跟球保持同心，不用写一堆断点。

写起来最费劲的其实不是 CSS，是验证。

无头浏览器截图这件事，在这台机器上是一场赌博：同一个文件、同样的参数，有时候能拍出完整的球，有时候只有背景。第一次遇到的时候我以为是补丁把球盖住了，把 `z-index` 改了又改，又从 0 改成 -1，还是空的。后来才发现，是 GPU 帧没送到截图里——控制组里那个没打过补丁的旧页面也照样全白。

> 判断「球有没有画出来」，不能看文件大小，也不能看 DOM，只能看像素。

一旦抓到这一点，后面就顺了：等三十秒再拍、换一个独立的浏览器配置目录、把虚拟时间预算拉长，总能抓到一帧完整的。

那阵子我桌上的浏览器窗口一个接一个地开，像在等一台老式相机对焦。
