这个站打开很轻，因为它真的只是几个文件。

没有 `package.json`，没有构建产物，没有 `npm install`。改一行 CSS，浏览器刷新就能看到。代价是：你得自己想清楚，怎么把这堆文件送上去。

最后落地的位置是 GitHub Pages 的一个子目录：`byuyan.github.io/nest/`。

为什么是子目录而不是一个独立的仓库？因为我先试过独立仓库。仓库建好了，文件也在，就是没有 Pages——那个仓库的 Pages 从来没被开启过，访问一直 404。而 `byuyan.github.io` 这个仓库本身已经有 Pages，把文件放进它的 `nest/` 子目录，天然就有一个能访问的地址。

推文件的方式有点野：本地打包成 zip，传到一个临时直链，然后往仓库里塞一条「一次性 workflow」。

它长这样：

```
on: push (只监听自己这个文件)
permissions: contents: write

steps:
  - checkout
  - curl 拉 zip → unzip 到 nest/
  - git add -A nest && 有 diff 才 commit + push
```

推上去大约五十秒到一分钟，Pages 就会重建。所以我一般等一分钟，然后请求一次带新版本参数的地址，确认状态码是 200、页面里确实是新版本号。

确认完就把那条 workflow 删掉。

这不是洁癖，是不想留一堆一次性脚本在仓库里——半年后回头看，你不会记得哪条 workflow 还在跑，哪条只是当时图省事留下的。

顺便说一个绕不过去的坑：静态站改完 CSS 或 JS，浏览器和 CDN 都可能还在用旧文件。解决办法很朴素，在所有引用后面加版本参数：

```
site.css?v=20261108h
splash.html?v=20261108h
```

改一次就递增一次。看着笨，但它救过我很多次——有一次改完 CSS 怎么刷新都没变化，折腾了十几分钟，最后发现只是缓存。

用笨办法，把时间省下来做别的事。
